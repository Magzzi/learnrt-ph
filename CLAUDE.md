## Direction: mobile app (planned)

The project is moving from this website to an Expo (React Native) Android/iOS app. Built so far: M0 (pnpm monorepo, `packages/core`), M1 (offline Expo app in `apps/mobile`) and M2 (Guided Ride). The Architecture Overview below describes the current website in `apps/web`, which will become a marketing-only site.

- Milestone specs and tickets: `docs/specs/`, `docs/tickets/`
- Unverified data and suspected errors: `docs/data-todo.md` (never "fix" data without an approved source)

### `packages/core` (`@learnrt/core`)

Platform-free shared logic, tested with Vitest (`pnpm test`). No React, Next, Node APIs or `fetch` in production code (enforced by `purity.test.ts`).

- `network.ts`: Lines, Stations (stable ids such as `lrt1-doroteo-jose`; look up by id, never by name), Line Status
- `nearest.ts`: `findNearestStations` (operational Lines by default)
- `fares.ts`: `getFare`, reproducing the website's fare rules; tables in `src/data/fares.ts` are generated by `pnpm --filter @learnrt/core convert-fares` from the `.xlsx` files, never edited by hand
- `graph.ts`: Line neighbours and bidirectional Transfers
- `route.ts`, `routeFare.ts`, `rideSteps.ts`, `rideProgress.ts`: Guided Ride. `planRoute` returns the fewest-Transfers route plus a fewer-stops alternative (no travel times exist); steps leave unknown entrances, platforms and walks as `null`; ride progress is a pure, JSON-serialisable state machine that also picks the geofence regions
- `landmarks.ts`, `learn.ts`: Landmarks and Learn content moved from the website
- `entrances.ts`: Station Entrances from OpenStreetMap, linked only through OSM stop areas (never by distance); `pnpm --filter @learnrt/core fetch-osm-entrances` refreshes the extract and regenerates `src/data/entrances.ts`
- Station positions come from OpenStreetMap: `pnpm --filter @learnrt/core fetch-osm-stations` refreshes `data-sources/osm-stations.json`, then `apply-osm-coordinates` writes them into `src/data/stations.ts`
- Every dataset exposes `lastVerified`; while it is `null` the app shows an Unverified label
- `src/test-support/` re-reads the website's `.xlsx` files and pages to prove the migrated data is unchanged; when M4b deletes those pages, those tests and their sources must move together

### `apps/mobile`

Expo SDK 58, Expo Router (`src/app`), NativeWind, i18next. Read `apps/mobile/AGENTS.md` first: always add packages with `npx expo install`. Logic lives outside `src/app` as pure, Vitest-tested functions (`src/map`, `src/fares`, `src/nearest`, `src/station`, `src/i18n`). Every rider-facing string goes through i18n; Filipino strings carry `review: "needs review"` until reviewed (launch gate, PRD §11). Station and Line names are never translated. Since M2 the app runs in a **development build**, not Expo Go (Expo Go has no background tasks on Android). Build and install it with `JAVA_HOME=~/.local/jdk/jdk-21.0.13+9 npx expo run:android` (Temurin 21; the system Java 25 has no compiler), then `npx expo start --dev-client`. Do not start Metro with `CI=1`: that turns off file watching and Metro keeps serving stale code. `android/` and `ios/` are generated (CNG) and git-ignored; configure native settings in `app.json`. `index.ts` is the entry so the geofence task (`src/ride/background.ts`) is defined before any screen. Local Android emulator: AVD `learnrt_api36` in `~/Android/Sdk`; it only runs headless with `-gpu swangle_indirect`, and location must be injected through the GPS test provider (the emulator's `geo fix` does not reach apps): `node scripts/gps-playback.ts <stationId> ...` plays a route. Geofences need the emulator's Location Accuracy setting on (ADR 0006). The street map's tile URL is the single value in `src/config.ts` (OpenFreeMap; never OpenStreetMap's own tile servers).

Styling (UI1): every colour is a role in `apps/mobile/src/theme/tokens.js` (light and dark, following the phone); use Tailwind role classes (`bg-page`, `bg-card`, `text-ink`, `text-muted`, `bg-accent`, `text-accentInk`...) or `useTheme()` for JS colours, never a raw colour. `tokens.test.ts` checks WCAG AA contrast and colour-blind distinction between Lines; add a pair there when you use a new text/background combination. Headings use the bundled Fraunces (`font-serif`); shared pieces are in `src/components` (`Card`, `PrimaryButton`, `SecondaryButton`, `ToggleRow`, `ScreenHeader`, `LegIcon`, `UnverifiedBadge`). Only `WelcomeArt` (artwork) is exempt from roles.

## Commands

pnpm monorepo (`apps/web`, `packages/*`). Run from the repo root:

```bash
pnpm install          # Install all workspace dependencies
pnpm dev:web          # Website dev server at http://localhost:3000
pnpm --filter mobile start   # Metro for apps/mobile (open in the development build)
pnpm --filter mobile android # Build and install the Android development build
pnpm build:web        # Production build of the website
pnpm test             # Run every package's tests
pnpm typecheck        # Type-check every package
pnpm --filter mobile lint    # ESLint for apps/mobile (expo lint)
```

`pnpm --filter web lint` runs `next lint`, which Next 16 removed; it fails and there is no ESLint config yet.

## Architecture Overview

**LearnRT** is a Next.js 16 (App Router) web app in `apps/web` for navigating the Philippine rail network (LRT-1, LRT-2, MRT-3, and upcoming lines). All pages are client components (`"use client"`). Paths below are relative to `apps/web`.

### Pages and their purpose

| Route | File | Purpose |
|---|---|---|
| `/` | `src/app/page.tsx` | Landing/hero with animated image carousel |
| `/explore` | `src/app/explore/page.tsx` | Expandable list of all rail lines with station lists and live open/closed status |
| `/trip` | `src/app/trip/page.tsx` | Fare calculator — select railway, ticket type, origin/destination |
| `/landmark` | `src/app/landmark/page.tsx` | Points of interest grouped by rail line and station |
| `/route` | `src/app/route/page.tsx` | Nearest station finder using geocoding + Haversine distance |
| `/stations` | `src/app/stations/page.tsx` | Placeholder ("coming soon") |

### Key utilities

- **`src/app/route/findnearest.ts`** — Contains the complete hardcoded station coordinate dataset for all lines (LRT-1 including Cavite extension, LRT-2, MRT-3, MRT-7). Exports `findNearestStations(lat, lng)` (Haversine, returns the top 3 with no distance cut-off) and `getCoordinates(location)` (Nominatim/OpenStreetMap geocoding).

- **`src/utils/FareMatrix.ts`** — Reads fare from `.xlsx` files in `public/` using the `xlsx` library. File naming convention: `{RAILWAY}-{type}-matrix.xlsx` for LRT-1/LRT-2 (type = `sjt` or `svf`), `MRT3-matrix.xlsx` / `MRT3-discounted-matrix.xlsx` for MRT-3. Discounted SJT for non-MRT3 lines applies 50% multiplier at runtime.

### Fare matrix files (in `apps/web/public/`)

- `LRT1-sjt-matrix.xlsx`, `LRT1-svf-matrix.xlsx`
- `LRT2-sjt-matrix.xlsx`, `LRT2-svf-matrix.xlsx`
- `MRT3-matrix.xlsx`, `MRT3-discounted-matrix.xlsx`

### Styling conventions

- Dark theme throughout: base background `#0a1a1a`, card/panel `#0d2222`, elevated elements `#1a2e2e`
- Accent color: **emerald** (`emerald-400`/`emerald-500`) for interactive elements; **yellow-500** for the primary CTA button
- Tailwind CSS v4 with `@tailwindcss/postcss`
- Framer Motion used for entrance animations (`opacity`/`y` transitions) on all pages
- Font: Roboto (Google Fonts) via `next/font`

### External dependencies to be aware of

- **`@react-google-maps/api`** — installed but not currently used in active pages; `src/components/ui/map.tsx` uses a plain `<iframe>` Google Maps embed instead
- **`@mui/material`** — installed but not used in any current page
- **Nominatim (OpenStreetMap)** — used for geocoding in the Route Finder; no API key required but subject to usage limits

### `next.config.ts`

Allows `next/image` to load from external domains: `images.unsplash.com`, `developers.google.com`, `img.icons8.com`, `i.postimg.cc`.
